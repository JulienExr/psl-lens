# PSL Lens V1.1 Implementation Plan

**Goal:** améliorer la base stable sans réécriture, suivant la mission Phase 2.
**Spec:** `docs/superpowers/specs/2026-10-18-v11-design.md`.
**Architecture:** moteurs purs conservés; annulation par propriétaire, géométrie
partagée, deux protocoles de score et cache progressif versionné.
**Tech Stack:** stack existante, sans backend ni appel LLM de calcul.

## Global Constraints

Traitement facial local, aucune persistance implicite, aucune validation physique
inventée. Score expérimental explicitement subjectif. Aucun merge/déploiement.
Les lots indépendants sont délégués selon dispatching-parallel-agents; interfaces
communes et intégration, cycle caméra et UI gérés ici. Revue indépendante finale.

## Review Focus

1. Ancien AbortSignal pendant une nouvelle inférence : seul son propriétaire est affecté.
2. Même géométrie après roll/translation/échelle : valeurs et dessin concordent.
3. Photo unique vs série dispersée : une fiabilité limitée ne justifie pas une note instable.
4. Vue oblique : contrôle de cohérence sans application des ratios frontaux.
5. Nouvelle version PWA : pas de mélange d’anciens et nouveaux moteurs/assets.

## Interfaces communes

`FrontalPSLResult extends PSLResult` : `reliability: limited|moderate|unavailable`,
`reasons: string[]`. `scoreFrontal(measurements, {source,quality})` pur.
`AggregatedAnalysis.frontalScore` ajouté à l’intégration, complet historique dans `score`.
`VisionClient.init(signal?)`, `detect(bitmap,mode,timestamp,signal?)` : annulation
nommée AbortError, anciens appels sans signal compatibles.
`buildMeasurementGeometry(detection,id)` : segments, axes, arcs et points dans
les pixels source, corrigés puis reconvertis; même scène pour SVG et Canvas.
Les agents modifient uniquement les fichiers de leur lot, aucun commit concurrent.
